## [0.1.0] — unreleased

First release. Everything in `specification.md` is implemented; see **Known limitations**
for what that does and does not mean.

### Added

**Repositories.** APT and RPM repositories, created through the interface with their
distributions/components/architectures or variants, their signing key and their retention
policy chosen up front. Every repository root is confined to a configured allow-list, and
the check is re-applied on every write rather than only at creation.

**Metadata that is always correct.** APT indices (`Packages`, `Packages.gz`, `Packages.xz`,
`Release`, `InRelease`, `Release.gpg`) are generated in pure Python from the database; RPM
`repodata` is generated by `createrepo_c` and its `repomd.xml` detached-signed. Regeneration
is always a background job, locked per repository, coalescing, and re-queued after an
unclean shutdown. Verified against a real `apt-get` and a real `dnf` in CI, including that
both *reject* the repository once its metadata is tampered with.

**Packages.** Upload and removal through the web interface or the API, with the stored path
derived from parsed metadata and never from the uploaded filename. A byte-identical
re-upload is a no-op success; a different file under an existing version is always refused.
One pool file can be published to several targets and is deleted only when the last one goes.

**Retention.** Optional per-repository limit on how many versions of each package are kept,
counted per name, per architecture, per publication target, using each format's own version
ordering. Enforced after each publish for the package published, with an explicit
"apply retention now" action for the backlog.

**Authentication and authorization.** LDAP login (search or direct bind, `memberOf` or
reverse group search, optional nesting), server-side sessions with idle and absolute
timeouts, periodic re-validation of group membership, CSRF protection enforced
application-wide, and two roles derived from group membership. Reading is unconditional and
anonymous.

**REST API.** `/api/v1` with scoped, expiring API tokens; anonymous reads, token-gated
writes, RFC 9457 problem documents, an OpenAPI schema and a reference page served from this
origin. A token can never do more than its owner's current directory role allows.

**Operations.** Background job queue with progress and logs; an append-only audit log; a
rescan that reconciles the database against the disk and reports drift without changing
anything; health and readiness probes; optional Prometheus metrics; in-process rate limiting
for logins, uploads and rejected tokens.

**Accessibility.** Built to WCAG 2.2 AA and verified with `axe-core` over every page, in
both themes, at two mount points, on every commit. Every flow works without JavaScript. See
[`docs/accessibility.md`](docs/accessibility.md), including what has *not* been verified.

**Deployment.** Sub-path aware under either proxy style, `X-Forwarded-*` honoured only from
configured proxies, a container image for `linux/amd64` and `linux/arm64`, and Alembic
migrations applied explicitly rather than on startup.

### Known limitations

- **Single instance.** The job queue and the rate limiter are in-process. Running two
  replicas gives each its own limits and needs the queue moved out of process first.
- **No manual screen-reader pass yet.** The automated accessibility suite passes; the
  human pass §11 asks for has not been done. See `docs/accessibility.md`.
- **Retention is version-based only.** No time-based expiry, deliberately: a stable package
  is not an abandoned one.
- **Source packages are not handled** — no `Sources` indices, `.dsc`, or SRPMs.
- **Packages themselves are never signed.** This application signs repository *metadata*;
  signing packages is the build system's job.
- **`createrepo_c` is invoked as a subprocess only.** The Python bindings path described in
  §4.2 is not implemented: a second code path that CI cannot exercise, producing output that
  must match the first byte for byte, is how a bug appears on exactly one host.
